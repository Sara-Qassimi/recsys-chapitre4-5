    Common thread · 2/2

    Four steps, always the same

    First diagnose what you know: how many ratings the user has, how many raters the item has, and the situation. Then choose how to combine the two methods, learn the weight or the rules on validation data, and finally decide where the context enters.
    01

    User-based vs item-based

    Mirror methods, different blind spots: why not use both?

    Explanation

    Strengths and weaknesses side by side

    Definition

    Hybrid recommender system: a definition

    A hybrid recommender combines two or more techniques so that the strengths of one cover the weaknesses of the other. Combining user-based and item-based CF is one of the simplest hybrids, because both read the same rating table. Similarity fusion combines both neighbourhoods in one prediction.

    Burke (2002)

    A hybrid recommender combines two or more recommendation techniques to gain better performance, with fewer of the drawbacks of any individual one. Here: user-based + item-based CF on the same rating table (similarity fusion, Wang et al., 2006).
    02

    Hybridization strategies

    Seven ways to combine recommenders (Burke, 2002), here with UB and IB.

    Overview

    Seven ways to hybridize

    Burke lists seven strategies. Some combine the outputs of the recommenders: weighted, switching, mixed and cascade. Others combine their data or their models: feature combination, feature augmentation and meta-level. The first four are by far the most common.
    StrategyIdeaExample
    Weightedone score = mix of scores0.75 × UB + 0.25 × IB
    Switchinga rule picks one methoduser with 1 rating → IB
    Mixedseveral lists shown togethertwo rows on a home page
    Feature combinationone predictor, both neighbourhoodssimilarity fusion (2006)
    Feature augmentationoutput of A = input of BUB fills cells → IB similarities
    CascadeA filters, B refinesIB top 100 → UB top 10
    Meta-levelmodel of A = input of Bitem similarities used to compare users
    Formula

    Weighted hybrid: one score from both

    The weighted hybrid is a weighted average of the two predictions. Both are already in stars, so they can be mixed directly. When the two methods almost agree, as for Alice and Inception, the mix changes little; it matters most when they disagree.
    Try it · move α between user-based and item-based
    Explanation

    Switching hybrid: a rule per situation

    A switching hybrid looks at what we know and picks the method that can compute an answer: item-based for a user with one rating, user-based for an item with one rater, popularity when there is nothing. It is simple and easy to explain, but its thresholds must be chosen carefully.
    Try it · which method does the rule choose?
    In a cascade, item similarities are computed once per night, so finding candidates is fast; user-based CF then ranks only these candidates. A mixed hybrid shows several rows, each produced by a different method; remove the duplicates between rows.
    These three strategies combine data or models instead of final scores. One formula can use both neighbourhoods at once, one method can fill the table for the other, or the model of one can be used inside the other. They are deeper but harder to build.

    03

    Learn the mix

    Choose the weight α on a validation set, never on the test set.

    Explanation

    Who chooses α? The validation set

    α is a setting like the number of neighbours K: we choose it on ratings that were hidden while computing the means and weights, called the validation set. We try several values and keep the one with the smallest error. The test set stays untouched until the very end.
    On these four validation ratings, item-based alone is poor and user-based alone is better, but the mix with α = 0.75 is the best of all. A hybrid helps when its parts make different mistakes, so that their errors partly cancel.

    Real world

    From one weight to many: the Netflix Prize

    The Netflix Prize was won by blending more than a hundred models, including many neighbourhood models like ours, with the blend learned on held-out data: a weighted hybrid at very large scale. Netflix later chose not to deploy the full blend, because the extra accuracy was not worth its engineering cost.
    04

    Context

    Time, place, companion: the rating also depends on the situation.

    Definition

    What is context?

    Context is anything that describes the situation of the user when they interact: when, where, with whom, on which device, in which mood. The same person may choose very different items on a weekday lunch alone and on a Saturday night with friends.

    When

    time of day, weekday, season

    Where

    home, cinema, city

    With whom

    alone, family, friends

    Device

    phone, TV, laptop

    Mood

    happy, tired, sad

    Weather

    sunny, rainy
    The user can tell us the context directly, the system can read it from the device or the log, or a model can guess it from behaviour. Reading it from the device costs the user nothing, but some context, like location, raises privacy questions.
    Explanation

    From U × I to U × I × C

    Chapters 4 and 5 fill a table of users and items. A context-aware recommender fills a cube: one table for each context value. The same user and item can have one rating per context, so Alice's rating of Toy Story alone says little about Toy Story with her family.
    Example

    Same movie, two contexts

    Toy Story is rated low when watched alone and high when watched with family, and Bob and Carol show this change themselves. The overall mean of 3.33 describes neither situation. A context-free system would never suggest Toy Story to Alice for a family evening.

    05

    Context-aware CF

    Pre-filtering, post-filtering, item splitting, with the formulas of Chapters 4–5.

    Overview

    Three ways to use the context

    The context can be used before the CF formula, by keeping only the data of the target context; after it, by adjusting the prediction; or inside it, by giving more weight to the neighbours' ratings made in the same context. The first two reuse the formulas of Chapters 4 and 5 unchanged.
    Simulator

    Context-free, pre-filtering and post-filtering

    We use the deviation formula of Chapter 4: the user's mean plus the average deviation of the other users who rated the item. For Alice and Toy Story it gives 3.47, the same number for an evening alone and an evening with family, because it ignores the context.
    Keep only the ratings given with family, then apply the same formula on this smaller data. Toy Story is liked in family evenings, so the prediction rises to 3.67. But only 6 ratings remain, Alice's mean comes from a single rating, and so do some deviations.
    First predict without context using all the data, then correct the result with what the family context changes for Toy Story: +1.33 star. The prediction becomes 4.80. Both methods now agree that Toy Story is a good choice for Alice's family evening.
    Try it · predict any (user, movie, context)
    Try this: Alice → Toy Story → Family: context-free 3.47, pre-filtering 3.67, post-filtering 4.80. Then Dave → Toy Story → Alone (Exercise 6).
    Explanation

    Contextual modeling and item splitting

    Instead of filtering before or after, the context can enter the formula: each neighbour's rating gets a weight that depends on how close its context is to the target context. A weight of 0 for other contexts is pre-filtering, a weight of 1 for all is the context-free formula.
    If a movie is rated very differently in two contexts, treat it as two movies: one for each context. User-based or item-based CF then runs on the new table, and each virtual item gets its own mean and similarities. Only split the items whose ratings really change with the context.

    Comparison

    Which paradigm when?

    Pre-filtering is the simplest but loses data, post-filtering keeps all the data but corrects with a simple rule, context-weighted neighbourhoods are a middle way, and item splitting only splits the items that need it. No paradigm always wins: compare them on validation data.
    ParadigmStrengthWeaknessUse it when…
    Pre-filteringsimple, CF unchangedless data per contextmany ratings per context
    Post-filteringuses all data for CFcontext rule added afterwardscontext changes a few items
    Context-weighted CFkeeps all data, favours the contextone more settingmedium data
    Item splittingany CF methodsplits datafew items depend on context

    Lab & limits

    Evaluate fairly, mind sparsity and privacy, then practise.

    Evaluation

    Evaluating hybrid and context-aware CF

    Tune every setting on validation data, compare with the context-free prediction on the same test ratings, and look at the results per group: users with few ratings, items with few raters, and each context. Also measure the coverage: a hybrid can predict cells that neither method can predict alone.

    Your hybrid improves the overall RMSE by only 0.5%. What do you check first?

    Limits

    Limits: complexity, sparsity, privacy

    Hybrids have two neighbourhoods to compute and store, and more settings to tune. Context divides the data across many situations, which hurts collaborative filtering most, must be collected, and can be personal. Add a component or a context dimension only if it really improves the error of the users it targets.

    Summary

    Back to our questions: what we learned

    User-based and item-based CF fail in different situations, so real systems combine them and learn the combination on validation data. Context changes ratings, and it can be used before, after or inside the CF formula, at the price of sparser data and privacy care.
